# 日志可靠性与 HTTPS 接入验收

2026-10-07，独立 Docker 测试项目 `waf-coraza-readiness-bench`。本轮实现日志磁盘缓冲、并行消费、统计查询优化与过期日志清理，以及 HTTP/HTTPS 同端口按域名接入。没有执行正式环境部署。

## 持续负载

Docker Desktop Linux，20 个逻辑 CPU、约 7.65 GiB 内存，WAF、Kafka、PostgreSQL、消费者、驱动和后端共享资源。Kafka 为一个 broker、三个分区、单副本；发布与消费各三个 worker。磁盘缓冲上限 1 GiB，每 5 ms 分组刷盘，500 条或 200 ms 封段。每组固定 32 并发、持续 200 秒，保留完整防护链路，复用 HTTP 连接。并行管理查询持续访问统计、30 天每日、7 天趋势和日志列表。

| 场景 | 请求数 | 请求/秒 | P95 ms | P99 ms | 错误/非预期状态 |
|---|---:|---:|---:|---:|---:|
| GET | 207,604 | 1,037.8 | 49.9 | 69.3 | 0 / 0 |
| JSON POST | 165,264 | 826.2 | 64.1 | 117.5 | 0 / 0 |
| 登录 POST | 152,797 | 763.8 | 69.4 | 133.8 | 0 / 0 |

共 525,665 次请求，新增 1,051,330 条事件。压测结束时发布缓冲已空，消费者 lag 为零；数据库收据总数 1,051,405，与包括先前功能回归在内的接受数量一致。请求日志 525,708、爬虫日志 525,688、弱口令事件 9，三类数量之和等于收据总数。重复请求日志、重复爬虫日志、孤立规则匹配均为零。

管理查询 1,904 次、失败零，最大耗时 5.385 秒。缓存与合并查询减少重复工作，但大数据量下全量统计仍可能持续数秒；本次没有设定或证明亚秒统计 SLA。HTTP 正常路径测的是内部明文连接；HTTPS 握手、证书与路由由独立真实集成测试验证，未压测 TLS 吞吐量。

本轮日志接受需要本地刷盘；此前 2026-10-06 的内存队列、短时峰值及其数据量/管理查询负载不同，不能据此计算严格性能提升或下降比例。当前可报告的是此配置在这十分钟内无丢弃、消费追平；不能把旧 GET 峰值约 7,000 请求/秒作为当前持久化链路的持续容量承诺，也不能把本轮数字推广到全天或其他硬件。

## 故障恢复

25 项恢复检查全部通过，原始结果在 `final/recovery.json`：

- Kafka 停机时磁盘缓冲存在 32,393 条事件、247,675,945 字节，丢弃为零；恢复后全部发送并入库。发送失败累计 17 次属于故障期间重试，不能解释为丢失 17 条日志。
- 停止消费者后数据库数量保持不变，Kafka 保留未消费事件；消费者重新启动后完整追平。
- PostgreSQL 暂停 30 秒后，三个 worker 均报告 `retrying`；恢复后事件计数完全一致。暂停期间没有向 WAF 发起新业务流量，此项只验证消费者数据库重试与 offset 保留。
- Kafka 不可用时先接受 11,144 条待发送事件（85,200,141 字节），然后 SIGKILL API。重启后 `recovered=11,144`，全部重放并入库。

最终数据库收据 1,283,965，请求日志 641,988、爬虫日志 641,968、弱口令事件 9；事件行总数与收据数一致。重复请求、重复爬虫与孤立匹配均为零。当前进程累计计数在 API 重启后归零，所以跨进程总量使用重启前的接受数量与数据库独立核对。

采样中 API 最大约 323 MiB、消费者约 128 MiB；数据库和 Kafka 包含共享缓存等占用，分别接近数 GiB。Docker 最终检查四个核心容器 `OOMKilled=false`、`RestartCount=0`；API 的 SIGKILL 后启动属于人工故障注入。资源原始采样见 `final/resources.jsonl`，不同容器的峰值不一定同时出现，不能直接相加。验收后已清理该专用测试项目。

## 验证边界

完整 HTTP 回归 116 项通过。Go 全量测试、`go vet`、前端 TypeScript 与生产构建通过。浏览器交互与视觉验收未执行。持续负载和故障注入不等于完整安全审计。

证书为人工导入，不含 ACME 自动续期或自动重定向。域名路由为精确匹配，TLS 最低 1.2，当前使用 HTTP/1.1。去重收据保留以避免重放复活，仍会持续增长。单 Kafka broker 仍是故障域，本地缓冲不保护已经进入 Kafka 的单副本数据；多 broker 集群本轮未新增。

本地恢复 CRS 运行规则时，Windows 安全软件隔离了四个上游攻击测试样例 YAML；运行规则未修改，构建排除上游 `tests` 目录。工作区 CRS 子模块因此显示测试样例缺失，不应将这些缺失提交成上游规则修改。

## 复现

详见 `scripts/bench/README.md` 和 `docs/https-and-logging.md`。隔离项目执行 `python scripts/bench/run_readiness.py --seconds 600 --concurrency 32`；镜像标识见 `image-id.txt`。首次小文件封段设计的未完成测试产物已删除，仓库保留 `final/` 最终验收数据。

GitHub 发布准备时移除了配置中的固定开发密码和 JWT 密钥，改为 `.env` 必填项，API 启动要求 JWT 密钥至少 32 字符；测试 Compose 使用明确标注的专用测试密钥。该发布配置调整再次通过 Go 全量测试和 Compose 配置检查，上述十分钟数据来自调整前记录的镜像；未重新进行十分钟压测。
