# 防护链路与模块边界

本轮保持 IP 白名单豁免及爬虫识别算法，调整统一执行模式、规则评分、CC 动作和请求审计。

## 请求路径

每次请求获取一份全局策略快照，依次执行 IP 白名单、黑名单、CC、爬虫、Coraza 请求头阶段、请求体大小限制、弱口令检测提交、Coraza 请求体阶段和后端转发。请求头阶段的拒绝不读取请求体；日志仅采集已读取内容，不能因此推断提前拒绝的请求没有正文。

`block` 执行检测模块的拒绝或等待动作。`monitor` 是全局观察模式：检测与计数仍运行，但不执行黑名单/CC/爬虫/规则阻断、CC 延迟或自动封禁。请求体大小限制、解析错误和依赖故障错误仍有效。观察模式中的爬虫事件实际动作是 `log`，拟执行动作保存在请求日志的 `detections` 中。

关闭防护总开关或命中 IP 白名单时，保持原来的模块跳过行为；请求体大小限制、日志和弱口令检测独立于这些豁免。

## 评分与规则

`score_threshold` 保留已有数值，含义调整为 CRS 入站异常分阈值，同时传入已编译的引擎策略及其缓存键。阈值覆盖在 CRS setup 之后、检测规则之前注入，不修改 CRS 子模块。`1000000001` 保留为内部阈值初始化规则 ID，不得在自定义规则中重复使用。

请求日志的 `risk_score` 从 CRS TX 变量读取；适配当前 CRS 的 blocking 分数与对应 paranoia level 的入站分数，不再累计命中规则的 severity。Coraza 插件变量接口依赖固定在引擎适配器内。自定义规则中的显式 `deny` 不依赖异常分阈值，因此评分为 0 也可能被直接拒绝。自定义规则若采用评分策略，需要在正文设置 CRS TX 分数变量；规则管理的目录评分仅作为备注。

新日志使用 `score_basis=crs_anomaly`；每个命中规则的 `score` 不再猜测其贡献，记录为 0，日志详情总分使用请求的真实异常分。历史日志保留原分数，前端明确标识旧口径。响应保持流式转发，当前仍不执行响应内容规则检测。

## CC 与自动封禁

CC 原子检查站点/IP 总限额与首个匹配 URI 限额；返回实际拒绝项的动作、规则及建议重试时间。URI `action` 省略时继承全局动作，总限额先检查。观察模式不等待或拒绝。

`delay` 表示在配置的最长等待预算内重新申请配额，不保证放行。每站点最多 64 个等待请求；队列满、预算耗尽或重检仍超限返回 429，并设置 Retry-After。客户端取消释放等待名额，取消请求记为错误。限流依赖故障保留 503 行为。

`internal/ser/autoblock` 单独协调规则拦截次数与黑名单写入。只有实际 WAF 阻断触发；CC、爬虫或观察命中不会隐式触发封禁。自动封禁失败不改变已经完成的阻断动作。

## 控制端、决策与审计

- 控制端校验并预编译规则策略，再保存全局配置。请求端复用相同参数编译的引擎，单次请求不重新读取其他版本配置。
- `pkg/proxy/decision.go` 保存检测建议，协调实际规则拒绝；`cc.go` 管理等待准入；反向代理主流程按顺序编排。
- `audit.go` 构建请求审计；正常转发、提前拒绝和错误返回均记录一次。记录模式、策略配置更新时间版本、检测建议及最终处理依据。配置版本不是规则文件内容版本。
- 爬虫模块仅检测并构建证据，主流程统一投递事件。事件模块负责磁盘缓冲、Kafka 发送与重试，消费者负责事务入库和去重；日志失败不改变业务判定。

请求日志增加可空审计字段，由现有 AutoMigrate 在应用/消费者启动时创建。应同时更新 API、消费者及前端，升级前备份数据库。验证先在隔离测试数据库完成，随后本地演示实例启动并验证新日志入库；未对外部生产环境执行部署。配置缓存过期且依赖读取失败时仍返回 503，未引入无限期使用过期策略的行为。通用 `/whitelists` 管理接口本轮未接入请求链路，只有现有 IP 白名单参与豁免。

## 验证

Go 回归覆盖真实 HTTP 后端、真实 Coraza、请求头拒绝不读取正文、请求体检测、各模块观察模式、白名单保持、错误审计、CC 排队上限/取消/重新准入、URI 动作返回契约、实际 CRS 高低阈值及重载、加权轮询并发分布。Redis 返回契约测试不替代真实 Redis Lua 集成测试。

前端执行 TypeScript 与生产构建，以及使用模拟 API 的浏览器验收。2026-10-10 已在独立 Docker PostgreSQL/Redis/Kafka 上设置 `WAF_INTEGRATION=1` 完成真实联调，包括 Redis Lua 超限项、Kafka 防护证据保存、目录分类与旧策略迁移；正式业务数据库未修改。普通 `go test ./...` 会跳过这些外部依赖测试。

规则分类与新增 PL 策略预设见 [规则分类说明](rule-classification.md)。
