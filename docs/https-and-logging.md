# 日志可靠性、存储治理与 HTTPS 域名接入

本轮范围：日志链路容量与可靠性、日志存储和统计查询、持续负载与故障验收，以及 HTTPS 和同端口域名接入。没有执行正式环境切换。

## 日志可靠性

生产发布器使用本地磁盘缓冲，默认目录 `./data/event-spool`，上限 1 GiB、3 个分片、5 ms 分组刷盘。Submit 在记录及目录刷盘完成后返回；请求不会等待 Kafka 或 PostgreSQL，但会增加本地磁盘写入/刷盘耗时。它不是零开销的异步日志。

分片并行发送，在同一日志段内分组刷盘确认；满 500 条或达到 200 ms 发布间隔才封段，避免每次刷盘都创建和重命名小文件。封段合并成最多 500 条的 Kafka 批次。Kafka 全部确认后才删除段文件。进程异常退出、发送成功但未删除时可能重放，由 PostgreSQL 的事件 ID 去重。启动恢复已刷盘数据；仅未确认的 `.open` 尾部不完整记录可以截断，完整记录校验失败或 `.wal` 损坏会阻止启动，不静默删除。目录由进程独占锁保护，不能让多个 API 共用同一 spool 卷。

磁盘上限达到、文件系统写入失败、事件超大或格式错误时 Submit 失败并计入丢弃/错误，业务请求继续处理。宿主机磁盘损坏、卷被删除或底层存储不兑现刷盘保证不在进程恢复保障内。Windows 测试使用文件刷盘；Linux 部署还对刷盘段目录执行 fsync。缓冲保留现有日志捕获内容，目录/文件分别使用 0700/0600 权限；本轮没有改变原始报文采集策略。

Compose 新增 `event_spool` 数据卷，普通 `docker compose down` 保留它。生产配置不可退回仅内存模式：配置加载要求有效 spool 目录。`OpenPublisher` 返回启动错误，只有专用测试构造器可显式使用无 spool 的内存队列。Kafka 初始不可用时 API 可以通过磁盘缓冲启动；依赖异常由运行监控报告，`/health/ready` 仍只是应用启动就绪。

消费者默认在一个 `log-consumer` 容器内运行 3 个独立 Kafka reader，作为同一消费者组的三个成员分担现有三个分区。每个 reader 保持自身批次的事务/offset 顺序，不把同分区不同批次并发提交。数据库成功提交后才提交 offset；Kafka fetch 错误持续重试，格式错误仍停止消费等待人工处理。弱口令告警的锁按接口排序，避免多 worker 反向取锁。心跳增加 worker/重试 worker 数、累计入库/offset 提交耗时和 fetch 错误计数。

当前仍为一个 Kafka broker、3 分区、单副本。本地缓冲改善发布端故障恢复，不能替代 Kafka broker 高可用。增加消费者容器/worker 时，活跃消费并行度受分区数限制；每个 API 实例需要独立 spool 卷。

Kafka 可以部署多个 broker 容器。若后续启用三 broker 高可用，需为节点设置独立 ID、监听地址与数据卷，配置 KRaft 控制器 quorum，并将业务主题及内部 offset 主题设为三副本，业务主题 `min.insync.replicas=2`、生产者 `acks=all`。现有单副本主题还需执行副本重新分配；只增加容器不会改变已有主题副本数。同一宿主机的多容器仍共享宿主机故障风险，跨主机部署才覆盖整机故障。本轮没有新增多 broker 部署。

运行监控与界面增加磁盘缓冲容量与待发送条数，占用超过既有 `queue_percent` 阈值产生 `log_spool` 告警。`accepted`/`published` 等累计数属于当前进程；`recovered` 是本次启动恢复的条数。没有错误时，排空后 `published = accepted + recovered`，跨进程验收还必须核对数据库去重收据。

## 日志存储和查询

- 总览通过 GROUPING SETS 一次扫描计算总数、评分/耗时均值和动作/站点/攻击类型分组；Top IP 和 Top 规则另外聚合。
- 每日统计和趋势各用一次时间范围聚合，空日期/时间桶由应用补齐。趋势查询限制在请求范围内，不再查询结束时间之后的数据。
- 攻击 IP 的类型集合在同一条聚合查询生成，移除逐 IP 的附加查询。
- 统计、每日、趋势和攻击 IP 使用默认 5 秒缓存，并合并相同缓存键的并发请求；最多 128 个键，失败不缓存，返回对象不共享可变状态。显式筛选边界不会被合并为另一个时间范围。
- 增加站点/动作/IP/攻击类型与时间的组合索引，以及规则匹配、爬虫与弱口令事件清理索引。并发索引创建在迁移事务之外执行；用非阻塞 advisory lock 轮询，避免等待锁查询持有快照与 CREATE INDEX CONCURRENTLY 形成死锁。

`log.retention_days` 默认 30，0 禁用自动清理；`cleanup_interval_minutes` 默认 60，`cleanup_batch_size` 默认 1000。每轮每类最多 20 个批次，整体 30 秒截止；请求日志及关联规则匹配同事务删除，爬虫日志和弱口令事件也按批清理。量很大时需多轮追平。手动旧请求日志清理接口每次处理一个有限批次，返回实际删除数量，可以重复调用。

操作审计、告警以及 `processed_events` 去重收据不会由自动清理删除。去重收据保留使历史事件重放不会重新生成已清理日志；它仍会增长，未来只能在建立可靠的 Kafka/spool 重放边界后再归档，不能直接套用 30 天清理。本轮采用过期删除而非另建归档存储，旧数据迁移仍需单独安排。

## HTTPS 与域名接入

在“站点管理”创建/编辑站点，选择 HTTP 或 HTTPS。HTTPS 导入/粘贴 PEM 证书链和未加密 PEM 私钥，证书链叶证书放在最前。保存时验证证书/私钥匹配、有效期，以及全部站点域名都在证书 SAN 覆盖内。更新时私钥留空保留已保存私钥，证书切换即时用于新连接。

同端口支持多个域名站点，通过 Host 匹配；HTTPS 在握手时根据 SNI 选择对应证书。域名大小写、末尾点及 IDNA 标准化；目前支持精确域名，不支持配置通配符路由（可以使用通配符证书覆盖多个明确域名）。同端口不能混用 HTTP 与 HTTPS，也不能重复配置同一个域名。HTTP 可以配置一个无域名默认站点，优先匹配明确域名，未命中时再回落到默认站点；没有默认站点时返回 404。HTTPS 必须配置域名，未知/缺失 SNI 拒绝握手，SNI 与 Host 路由到不同站点返回 421。

TLS 最低 1.2，目前协商 HTTP/1.1。证书更新不重新绑定端口，共享监听器在最后一个站点退出后才关闭。证书过期后新握手被拒绝。此版本提供人工证书导入，没有自动申请/续期或 HTTP→HTTPS 重定向。

私钥使用 AES-256-GCM 加密后保存在数据库，不会在站点列表/详情、操作日志中回显。加密主密钥首次创建在 `proxy.tls_key_file`，默认 `./data/tls/master.key`；Compose 新增 `tls_keys` 卷。备份/迁移须同时保留数据库和该主密钥，丢失密钥无法解密已保存私钥。证书上传应通过受保护的管理网络/管理入口。

Compose 将宿主机 443 映射到 WAF 的 443。使用该端口时在站点选择监听端口 443，域名 DNS 指向 WAF 所在主机。宿主机 80 目前用于管理界面；HTTP 站点可沿用 9000–9009，新增其他端口需要同步发布。真实客户端 IP 仍使用直连来源，当前没有启用信任外部 X-Forwarded-For。

API 新增字段：`tls_enabled`、`tls_certificate`、只写 `tls_private_key`；已有 HTTP 站点默认为 `tls_enabled=false`。启用、更新失败会回滚数据库配置，保留原运行配置。

## 验证与复现

Go 单元测试覆盖并发磁盘提交、容量上限、重启/强制退出重放、尾部截断、完整记录损坏拒绝、独占锁、私钥加密和域名规范化。真实集成测试覆盖共享 HTTP/HTTPS 端口、SNI 证书选择、域名前置伪装拒绝、证书热更新、失败更新保留旧证书、共享端口启停，以及统计缓存、清理与重放不复活。三进程独立初始化全新临时数据库回归索引创建死锁。

持续负载与恢复工具见 `scripts/bench/run_readiness.py`。默认三种流量各 200 秒、32 并发，同时每秒循环查询统计、30 天每日、7 天趋势及日志列表；随后注入 Kafka 停机、消费者停机、PostgreSQL 暂停和发布器 SIGKILL。数据库总量、重复记录和孤立匹配独立核对，不单凭 HTTP 状态认定日志完整。数据与资源采样写入 `docs/benchmarks/latest`。

```powershell
go test ./...
go vet ./...
cd web1
npm install
npm run build
cd ..
python scripts/bench/run_readiness.py --build --seconds 600 --concurrency 32
```

执行前确保 15432、16379、29094 测试端口空闲。脚本仅允许 `rwaf-readiness-*` 项目名，默认保留测试栈供检查；加 `--cleanup` 才删除该项目临时数据卷。构建需要可用的镜像仓库/Go 模块网络。最终本机结果单独记录在本日期的验收报告，不把十分钟测试当作全天稳定容量或其他硬件的承诺。
