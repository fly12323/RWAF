# 规则分类、误报风险与策略预设

规则目录保留原始 CRS 规则正文，以防护用途、检测阶段、CRS PL 检测强度和相对误报风险组织。严重级别表示攻击危害，不表示检测准确率；目录备注分数不参与运行时拦截。

## 分类依据

- 防护用途：协议、SQL 注入、XSS、文件包含、命令执行、PHP、Java、通用应用攻击、扫描器、会话攻击、数据泄漏等。CRS 934 是通用应用攻击，包含 Node.js 特征，并非全部规则只针对 Node.js。策略接口保留 `nodejs` 键以兼容已有配置。
- 检测强度：按规则原始 `paranoia-level/N` 标签显示基础、扩展、严格、极严格检测。PL 标签缺失时显示待评估。
- 误报风险：PL1/2/3/4 分别标为较低/中等/较高/很高。这是依据 CRS 调优需求的相对估计，不是本系统测得的误报率，也不保证低风险规则不会误封。
- 初始化、排除、分数决策、关联及跳转规则单独归为引擎辅助，不参与攻击检测效果排名。自定义规则始终需要人工评估，不从其自报的严重级别、备注分数或 PL 标签推定准确性。
- 请求、响应、引擎辅助可分别筛选。当前代理只执行请求阶段；响应规则虽存在于目录，却未执行，页面明确标识。目录启用标记也不代表实际策略启用情况。

规则详情给出风险依据和业务调优重点，如富文本、搜索、代码输入、路径参数。风险与阶段筛选在分页前应用，总数覆盖全部符合条件的目录规则。Profile 由正文实时派生，不增加规则表的分类元数据列。

## 策略预设

| 预设 | PL | 入站异常分阈值 | 取舍 |
| --- | --- | --- | --- |
| 低误报优先 | 1 | 5 | 基础检测，调优需求相对较低 |
| 均衡防护 | 2 | 5 | 扩展覆盖，需验证富文本、搜索、代码等正常输入 |
| 严格防护 | 3 | 5 | 更多严格检测，误报调优需求较高 |

PL4 可手动设置。三个预设使用相同阈值，不通过提高阈值掩盖误报，因为单条攻击可能只有 5 分。低误报是相同阈值下相对其他 PL 而言；从已有阈值 15 切换到预设阈值 5，仍可能增加拦截。

选择预设只填入表单，保存后才对所有站点生效。保留当前执行模式、分类范围、禁用 ID、模块开关和 CC/名单/爬虫配置。分类与禁用 ID 仍可能降低覆盖范围，自定义显式 deny 也不受异常分阈值控制。先观察和回放业务样本，再决定是否启用更高 PL 的拦截模式。

`paranoia_level` 加入全局策略表，旧行由 AutoMigrate 补为 1，未提交该字段的旧客户端按 PL1 处理；已有异常分阈值和其他配置保留。请求端与控制端使用同一参数编译规则，并将 PL 纳入策略缓存键及热重载规格。变量覆盖在 CRS setup 之后注入 `blocking_paranoia_level` 和 `detection_paranoia_level`，不修改原始文件。内部策略规则 `1000000001` 不允许禁用。

## 验证与局限

2026-10-10 在独立 Docker 测试栈验证 PostgreSQL 旧策略迁移、真实 Redis Lua 超限项/动作/重试时间、Kafka 日志证据保存、分类筛选与分页，以及代理全局模式切换。原始 CRS PL2 规则 `942120` 在 PL1 跳过、PL2/3 命中，重载后保持行为。前端生产构建及模拟 API 的浏览器交互验证覆盖分类筛选、响应未执行提示、预设填入和保存参数。

这些检查验证功能及策略生效，不构成攻击检出率、误报率或吞吐能力的测量。随后本地演示实例在 PL1/5/block 下完成定向验证，日志保留；未对外部生产环境执行部署。

后续完成的 [PL 等级与阈值样本评估](benchmarks/2026-10-10/accuracy.md) 已测出具体误封与未阻断比例，并发现 JSON 处理器接入缺口及编码 Cookie 探针问题。该报告是受控样本结果，仍不代表实际业务误报率；预设需先校准业务，不应仅凭名字直接上线。
